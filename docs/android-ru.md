# Mesh2Motion для Android — тестовая версия 0.1

Приложение запускает редактор Mesh2Motion локально внутри Android WebView.
Модели, скелеты и анимации из репозитория включены в APK. Сетевое разрешение
приложению не требуется. Модели пользователя не отправляются на сервер.

## Установка

- Android 8.0 или новее, устройство с OpenGL ES 3.0 / WebGL 2.
- Обновлённый Android System WebView (на некоторых устройствах — Chrome).
- Установить `app-debug.apk`, разрешив установку для приложения, которым открыт файл.

Это debug-сборка для проверки, не выпуск для Google Play. Debug-ключ локальной
сборки может отличаться от ключа GitHub Actions: при смене источника APK Android
может потребовать удалить предыдущую установку. Экспортируйте работу перед этим.
Для стабильных обновлений релиза нужен постоянный ключ подписи владельца проекта.

## Работа с персонажем

1. В `Use Your Model` нажать Upload и выбрать GLB или FBX. GLTF, BIN и текстуры
   предварительно сложить в ZIP с сохранением структуры каталогов.
2. Повернуть персонажа лицом вперёд, выбрать тип и масштаб скелета.
3. Совместить суставы с телом спереди и сбоку. Кнопка «Скрыть панель» освобождает
   экран телефона. Подходящая исходная поза — T или A, с руками отдельно от тела.
4. Если руки захватывают торс, включить `Use Arm Plane Correction` и проверить
   положение разделителей. `Use Head Weight Correction` предназначена для больших
   голов: она больше не назначает голову вершинам ниже головного сустава.
5. Проверить несколько анимаций, включая ходьбу и поднятие рук, выбрать нужные
   анимации и экспортировать GLB или FBX. Android предложит папку и имя файла.
6. Если у модели уже правильный скелет, использовать `Use Your Rigged Model`
   для переноса анимаций с сохранением исходного рига.

Автопривязка остаётся геометрическим алгоритмом. Она не гарантирует корректность
любой модели: сомкнутые руки/ноги, поза сидя, сильно перекрывающая тело одежда и
необычные пропорции могут потребовать ручной правки. Исходный проблемный файл
пользователя пока не предоставлен; его конкретные искажения ещё не проверены.
Нативный экспорт ограничен 256 МБ; потребление памяти при импорте зависит от модели.
Не закрывайте приложение до завершения экспорта: проект пока не сохраняется автоматически.

## Что исправлено

- Расчёт области таза сравнивает координаты Y в одной системе, а не расстояние
  луча с высотой вершины. При отсутствии пересечения на отдельном предмете одежды
  таз не исключается из возможных влияний.
- Коррекция головы не переносит вершины пояса/торса на голову при слишком низком
  пользовательском разделителе.
- При повторной привязке импортированной модели сохраняется видимая поза
  SkinnedMesh и морфов до удаления старого скелета. Скелет клонируется отдельно
  от оригинала; материалы и относительное положение отдельных частей сохраняются.
- Сохранение идёт порциями по 192 КБ с подтверждениями и проверкой длины файла.
  Успех показывается после записи файла; отмена сохраняет модель в редакторе.
- В сборку больше не попадает весь `process.env`; сохраняются только два
  публичных поля версии Cloudflare.

## Сборка

Нужны Node.js 24, JDK 17, Android SDK Platform 35 и Build Tools 35.0.0.
Gradle Wrapper 8.11.1 включён в репозиторий и проверяет SHA-256 дистрибутива.

```sh
npm ci
npm test -- --run
npm run android:build
```

Переменная `ANDROID_HOME` должна указывать на SDK. Альтернатива — файл
`android/local.properties` с `sdk.dir=/путь/к/android-sdk`. На Windows после
`npm run build` можно запустить `android\gradlew.bat -p android assembleDebug`.

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.
В GitHub Actions workflow **Android APK** создаёт скачиваемый артефакт
**Mesh2Motion-Android-debug**. Для release-подписи не добавляйте ключи в git.

## Проверка перед использованием на телефоне

Автотесты покрывают ошибку таза, ограничитель головы, сохранение позы тела/одежды,
передачу файла порциями и отмену экспорта. Проверяются веб-сборка и Android-сборка.
Физический телефон в этой среде недоступен. На своём устройстве проверьте импорт,
перемещение суставов пальцем, воспроизведение, сохранение, повторный импорт
полученного GLB, отмену сохранения и поворот экрана.

В исходном проекте есть ошибки полного `tsc --noEmit`; Vite собирает приложение
без полного typecheck. Этот отдельный долг не скрывается Android-сборкой.
